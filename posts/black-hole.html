Rendering a black hole on the GPU

2026-06-12 · CUDAphysics

For my CS 179 (GPU programming) final, Kevin Peng and I built a real-time renderer for a Schwarzschild black hole. Kevin wrote the geodesic integrator; I wrote the camera, the shading, and the CUDA rendering kernels. Code on GitHub.

The trick: stay in the plane

Schwarzschild spacetime is spherically symmetric, so every photon's path lies in one fixed plane. Instead of integrating the full 8-dimensional phase space, each ray integrates three numbers in polar coordinates (r, φ) — which halves memory bandwidth on the GPU:

dr/dλ   = v_r
dv_r/dλ = L²(r − 3) / r⁴     ← exact Schwarzschild geodesic
dφ/dλ   = L / r²

Near the photon sphere (r = 3) curvature gets intense, so the RK4 step size shrinks adaptively. Each ray ends up captured by the horizon, hitting the accretion disk (shaded as a blackbody), or escaping to the starfield skybox.

On the GPU

Every pixel is independent, so the double loop becomes a CUDA kernel with one thread per pixel in 16×16 blocks. On top of that: bloom and HDR tone mapping as post-processing kernels, Doppler beaming on the disk, and a browser viewer where you can orbit, zoom, and tweak the physics live.

Keeping it honest

Pretty pictures are easy to fake, so we wrote a physics test suite against general relativity:

testresult
weak-field deflection vs. GR (b = 50)0.44% error
photon sphere capture at b = 3√3captured / escaped correctly at ±0.1
energy + angular momentum drift~10⁻⁶
time reversalretraces within 0.16%
spherical symmetry1.8 × 10⁻⁷ max error

Plus CPU–GPU parity tests so the CUDA port matches the reference implementation.

The little black_hole.cam in the sidebar is a much simpler cousin: a thin-lens approximation in a WebGL shader, not real geodesics. Still fun to hover.
